- **前置理解：** 7A 的回归集、Ragas 裁判与允许列表追踪；7B 的记忆生命周期；2C 的冻结保留集；4C 的消融记录
- **验证状态：** 现有 CI 只跑无密钥 pytest；评测脚本仍只调用词法检索器；记忆实现在内存中、未接入 API。
- **节奏：** 建议 3 次：评测适配主线 → 门禁与阈值 → 记忆接入与删除传播。
- **学习规则：** 门禁阈值来自已记录的基线，不为让 CI 变绿而下调；裁判分数必须经人工校准。

## 1. 问题：现在为什么需要它？

到阶段 7 主线已经有分块、向量、混合、模型、身份和工单。任何一处改动都可能让某类题变差，而人工重跑不可持续。需要一条自动的门禁：固定数据、固定阈值、失败即阻止合并；同时记忆功能要进入主线，并且删除要真正传播。

## 2. 原理：在这个问题里理解技术

- **评测适配块级主线：** 返回块时先经 `parent_id` 映射到文档、按首次出现去重，再算文档级指标；块级指标另报（对应 [回归跟踪](../course/regression-cases.md) 的对照规则）。
- **两层门禁：** 无密钥层（词法/固定向量夹具、权限与拒答用例）在每次 PR 跑；在线层（真实模型、保留集）手动触发或定时跑，结果写回仓库。
- **阈值怎么定：** 取最近一次通过验收的基线减去允许波动；分类别设阈值，权限与拒答类零容忍。
- **记忆接入：** 只保存定义好的偏好；user/tenant/TTL 存 PostgreSQL；删除传播到缓存、向量 payload 与日志（对应 [集成合同](../course/integration.md) 第 5 项）。

## 4. 跟着运行与关键实操

1. 在本地用主线 API 跑开发集，得到分类别指标；把它们写成阈值文件。
2. 故意把混合检索开关关掉提交 PR，观察 CI 门禁失败并指出是哪一类题退化。
3. 保存一条偏好后跨用户读取，预期不可见；撤回后立刻再问，预期不再影响回答，且缓存不命中。
4. 用 20 条抽样做裁判校准；一致率低时先修 rubric，不改评测集。

**闭卷小实现（10–20 行）：** 实现 `to_document_level(chunk_hits, parent_by_chunk) -> list[str]`（去重保序）与 `gate(metrics, thresholds) -> list[str]`（返回未达标项）；导师给测试。

## 5. 验证与排错

- 门禁失败信息能直接指向类别与题号，而不只是一个总分。
- 追踪上传只含允许列表字段；用抓包或日志证明，不只看前端。
- 记忆删除后，向量库与缓存中不存在残留（写测试查 payload）。
