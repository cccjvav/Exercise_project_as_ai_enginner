## 1. 问题：现在为什么需要它？

4A 说"查询分词由调用者负责"，但课程从没教过中文分词，固定词表只是教学基线。没有真实分词，BM25 在中文语料上就是假的；没有接入主线，混合检索永远是实验脚本；没有在 ≥20 份文档上对照，"混合优于单路"只是口号。

## 2. 原理：在这个问题里理解技术

- **中文分词的两条便宜路线：** jieba（词典分词，可加领域词）与字符 n-gram（无词典、对新词稳健、索引更大）。先各跑一遍词法基线，看哪一种让 q06 类换说法题变化。
- **融合在主线里的位置：** 服务端身份过滤 → 词法候选 + 向量候选 → RRF → （可选）重排 → 父级扩展 → 生成。每个开关都是配置项，默认关闭，便于单因素对照。
- **消融的最低要求：** 固定语料版本、题集哈希、模型名/版本、k、随机种子；报告分母；配对看逐题差异；权限与拒答回归不能被均值改善抵消。

## 4. 跟着运行与关键实操

1. 用 jieba 与 2-gram 分别重跑词法基线，记录 q06/q06b 的变化。
2. 打开 `hybrid` 开关，在开发集上与向量单路配对比较 Recall@5、MRR；找出一道变好、一道变差的题，读它们的候选与原文。
3. 只打开一个附加策略（重排或多查询）再跑一次；费用/延迟一起记。
4. 在保留集上只跑一次最终配置，填入模板；没跑的行写"未运行"。

**闭卷小实现（10–20 行）：** 实现 `ngram_tokens(text, n) -> list[str]`（保留词频、跳过空白与标点），导师给测试；再实现 `paired_delta(a, b) -> list[tuple[str, float]]` 输出逐题差值。

## 5. 验证与排错

- 分词器切换不改变金标准；同一问题不同分词器的候选差异能用原文解释。
- 消融记录里每个数字都能回溯到命令、数据哈希与模型版本。
- 保留集只跑一次；再想调参数就得承认它已变成开发集。
