## 1. 问题：现在为什么需要它？

三份手册、八道题上，`k=3` 的任何无阈值检索器 Recall@3 都是 1；`limit=2` 时连随机检索的期望 Recall 也有 2/3。用这样的数据比较词法、向量、混合和重排，得到的差异主要来自语料太小，而不是方法。阶段 3–4 的每一个"改善"都会不可信。

数据管道阶段本来就要面对"文档多、长、杂、会更新"。所以在进入向量检索之前，先把能让实验有意义的语料和题集建起来。

## 2. 原理：在这个问题里理解技术

- **开发集与冻结保留集：** 开发集用来看逐题输出、调参数；保留集只在阶段末比较，看过它的输出后不能再调参数。记录两者的 SHA256，任何修改都要换版本号并说明理由。
- **题目类别决定你能发现哪类失败：** 精确词、换说法、多跳（条件在 A 结论在 B）、有关键词但无答案、版本冲突/过期、权限受限（只有某租户可见）、歧义需澄清。每类至少 5 题，否则该类指标只是噪声。
- **k 与文档数：** Recall@k 只有在 `k ≪ 文档数` 时才能区分方法。语料 ≥20 份文档、块级检索时 ≥100 块，`k=3/5` 才有意义。
- **虚构但逼真：** 同一主题多份版本、近重复段落、跨文档条件、不同租户归属，这些是真实企业知识库的常态，也是后面权限、版本、幂等课程的测试材料。

## 4. 跟着运行与关键实操

1. 导师生成 20–40 份 Northstar Cloud 虚构手册（每份 1–3 千字，含至少一份多页 PDF 供 2B 复用），并生成清单。
2. 学习者阅读手册后**亲手标注** 40–60 道题：写问题、`answerable`、相关文档 ID、`reference_facts`、类别、租户；其中包含把原 q06 拆出的 `q06b`（显式带 Webhook 上下文），原 q06 归入"歧义"类。
3. 导师复核标注（不看保留集答案逐题调整词表），记录分歧与裁定。
4. 划分：开发集约 70%，保留集约 30%，各类别按比例；记录两个文件的 SHA256 到 [回归跟踪](../course/regression-cases.md)。
5. 在新语料上重跑词法基线，作为阶段 3–4 的对照起点；q06/q09 的状态迁移到新表。

**闭卷小实现（10–20 行）：** 导师给出签名与测试，学习者实现 `split_dev_holdout(rows, ratio, seed) -> tuple[list, list]`，要求按 `category` 分层、可复现、两侧 ID 不重叠。

## 5. 验证与排错

- 清单中的 SHA256 与文件一致；文档 ID 唯一；每题的相关 ID 都存在于语料。
- 每个类别的题数 ≥5；保留集不含与开发集完全相同的问题文本。
- 词法基线在新语料上的 Recall@3 明显低于 1，否则说明语料仍不足以区分方法。
