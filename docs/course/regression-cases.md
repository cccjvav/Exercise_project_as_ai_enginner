### q06 的口径与验证条件

- 原标注假设上下文已明确讨论 Webhook，独立一句“消息”有歧义。
- 保留原问题、语料和相关 ID；不能仅给新方案的问题偷偷加上 Webhook，再和原方案当成同输入比较。需要显式上下文或澄清时，另列实验条件。
- 在固定 k、同一评测集上记录实际返回文档与位置，检查相关父文档 webhook-delivery 是否被找回，同时检查其他题是否退化。
- 手写几何向量、fixture 排名或讲解预期不是语义检索改善证据。一次演示命中也不能证明全部同义表达都得到解决。

### q09 的两个验证层次

1. **检索层：** 保留阶段 1 的无答案题空返回率，记录是否仍返回无依据候选，不因换阶段偷偷改分母或删除失败题。
2. **回答层（接入模型之后）：** 可以拿到相关背景却仍缺少收费事实；必须核对是否明确表示当前证据不足、不编造价格或免费政策。记录回答、引用和人工证据核对结果。

这两层不是同一个指标。如果生成端能正确说明证据不足，但检索仍返回背景，只能分别报告“该条件下回答侧通过检查”“检索空返回目标仍未达到”，不能改写成两个问题都已解决。引用 ID 合法也不能独自证明内容支持答案。

- 修订语料或标注要说明理由并保留旧版本，不为了好看的分数改金标准。新发现的反例也进入跟踪，而不只照顾这两题。
