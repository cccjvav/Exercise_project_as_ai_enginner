# EvidenceDesk 作品集说明模板

## 一句话价值

为哪个用户解决了哪个具体问题？不是“集成了 N 个框架”。

## 实现边界

| 能力 | 已实现组件 | 已集成应用 | 已实测 | 未完成/限制 |
|---|---|---|---|---|
| 带引用 RAG | | | | |
| 无答案处理 | | | | |
| 用户与权限 | | | | |
| 受控工单 | | | | |
| 评估与记忆 | | | | |
| 部署与监控 | | | | |

数据是虚构/获准资料吗？哪些代码为导师提供参考、哪些关键改动和实验由学习者完成？

## 架构与决策

附数据流和权限流；解释为什么选择当前技术，以及为什么没选更复杂方案。

## 复现

代码提交、依赖快照、数据哈希、配置名（不含密钥）、安装/运行/测试命令、机器条件。

## 结果与失败

链接实际生成的报告。只有词法基线就只声明词法指标，不将开发题的 5/6 写成真实客户问答准确率。

至少列一个失败及根因；说明仍需的在线模型、真实部署、浏览器与安全验收。

## 3–5 分钟演示

1. 用户问题与依据；2. 无依据的反例；3. 权限隔离；4. 审批拒绝/重试；5. 对照和限制。

未集成的组件可单独演示，但必须明确“这是组件实验”，不剪辑成已完成端到端应用。

## 简历草稿（填写实测值，不照搬括号）

“构建基于 [已验证方案] 的知识检索/问答原型，提供 [实际能力]；在 [数据规模及类型] 上，对比 [方案]，观察到 [实际指标]；通过 [测试] 验证 [边界]。”

## 待办与复盘

你能解释并修改哪些关键逻辑？下一步最大的真实风险是什么？
