# 怎样维护逐行教材

[源码目录](index.md) · [检查器精讲](tools--check_course_py.md) · [旧课程同步器精讲](tools--sync_course_sources_py.md)

## 修改实现以后，按这个顺序做

1. **先确认范围。** `git diff -- <源文件>` 看实际改了什么；新增受维护的业务/示例/测试/工具/前端文件要加入覆盖清单，不把用户本地笔记或临时实验自动收进来。
2. **更新完整源码。** 修改对应 `docs/code/` 页的完整副本；保留 `<!-- source: 相对路径 -->`。源码本身含三个反引号时，本页使用 `~~~` 围栏，避免截断；片段使用一致的围栏规则。
3. **人工重读每条受影响的解释。** 不仅改数字：调用参数、异常顺序、数据结构、权限与副作用可能已经变化。每个 `第 N 行` 对应 `<a id="LN"></a>` 和该行片段；插入/删除行后续编号都要调整。空行/注释也保留编号，但业务执行行不能用“这一行执行逻辑”之类空话代替解释。
4. **更新例子和关键练习。** 重新检查预期来自源码还是实际运行。不要把模型mock、固定排名、用户预测改写成真实外部服务结果，也不要改旧问答让过去错误看起来从未发生。
5. **更新 `manifest.json`。** `files` 是逐行主清单，`supplementary` 是配置/维护清单。每条含 `source`、`page`、`sha256`（原始文件字节的SHA256）、`line_count`（UTF-8文本splitlines行数）；主清单另有 `explained_lines`（1到末行的完整序列）和 `specific_notes`（本次针对具体行编写说明的编号，其他行使用导入/注释/空行等共通语法说明）。新增或移动代码时也复核这项分类。`coverage` 区分 `individual-lines` 与 `purpose-and-maintenance`。**不能只刷新hash让错误解释继续通过。**
6. **更新课程入口与数量。** 源码目录、覆盖清单、对应小课链接一起审查；变化后的分母由实际清单产生，不能永久写“全项目51份”。
7. **运行机械检查和相关测试。** `python tools/check_course.py`；按改动范围运行 `python -m pytest -q -rs`、前端构建等。联网/外发/写库/部署不是机械检查的一部分，仍需相应阶段确认。
8. **审查最后diff。** 只提交明确相关文件，不使用无差别 `git add .` 把学员草稿或秘密纳入；本地保存、提交、推送、远端CI通过四种状态分开报告。

## 只读核对一个文件的摘要和行数

例如在仓库根目录：

```bash
python -c 'from pathlib import Path; import hashlib; p=Path("src/evidencedesk/ingest.py"); raw=p.read_bytes(); print(hashlib.sha256(raw).hexdigest(), len(raw.decode("utf-8").splitlines()))'
```

按顺序：导入路径与摘要工具 → 指定文件 → 读原字节 → 打印SHA256与解码后的物理行数。此命令不改清单、不更新解释，也不运行 `ingest.py`。不要把校验值更新当成人工审读的替代。

## 两个维护工具的职责不同

- `check_course.py`：只读检查链接、完整源码副本、逐行清单摘要/编号、部分Python目录语法和22课数量；可以由CI运行。
- `sync_course_sources.py`：**会写**旧 `docs/lessons` 模板中的源码副本和“逐行／相邻语句”概括表。它不维护新的 `docs/code` 逐行说明；不能用自动摘注释替代本轮细读材料。

当前检查器是受控Markdown格式的正则校验，不是完整CommonMark解析器：不验证所有页内标题锚点、远端URL可达性或解释语义。每行有标题也不自动达到1A细度，仍需检查具体语法、数据变化、设计理由、反例与练习是否准确。
