# 练习数据说明

`sample/` 下三份 Markdown 是为本课程原创的纯虚构语料，不含真实企业数据、个人信息或有效凭据，可以随项目保留用于复现。产品、时限、流程均为练习设定，不应当作真实生产安全规范。

`questions.jsonl` 每行一个 JSON 对象：

- `id`：唯一问题 ID。
- `question`：检索输入。
- `answerable`：当前固定语料能否回答。
- `relevant_document_ids`：人工标注的依据文档 ID，即 Markdown 文件名去掉扩展名。
- `reference_facts`：人工摘要，用于人工核对，**不得作为检索输入、训练数据或程序答案映射**。
- `category`：便于按失败类型分析。

这些是 8 条公开开发题，数据很小，不能当作最终测试集或生产效果证据。阶段 1 的 q06 刻意不含领域词，用于观察词法基线的局限。其人工标注假设会话已明确在讨论 Webhook；JSONL 的 question 本身并未携带这个上下文，因此这是受限教学样例。没有该上下文时应先澄清“消息”类型，不能把它当作通用单轮问答的确定标签。当前不偷偷更改评测输入；后续设计多轮评测时再显式编码上下文并记录数据版本。q07/q08 没有关键词，不足以证明拒答鲁棒；学习者还需补充“有关键词但无答案”的反例。

后续新增外部数据时，先核对来源、授权、隐私、更新日期，再设计文档版本及留出集；不将大文件、客户数据或自动下载数据直接提交到 Git。
