# EvidenceDesk · 有据可查的企业知识与工单助手

面向 AI 工程师求职的**项目驱动学习仓库**：先遇到问题，再由导师提供可运行示例并逐行讲解；学习者只在关键处按步骤实操，通过预测、改动和测试验证理解。

> 当前状态：学习项目启动，准备进入阶段 1。仓库包含课程、虚构练习数据、评测样例和一个可运行的文档读取示例，**尚未实现检索或问答应用**，不代表已具备生产能力。

## 要做什么？

为一家虚构 SaaS 公司的内部支持团队构建助手：从产品手册和运维流程中找到依据，回答时引用来源；没有依据时明确拒答；后续在权限校验和人工确认下生成、提交工单。主要用户是支持工程师和运维人员。

示例问题：“Webhook 失败后怎么重试？” → 检索手册 → 给出带引用的说明。

反例：“年付折扣是多少？” → 知识库没有价格信息 → 不编造。

最终目标包括：可部署的前后端、可复现的数据管道、RAG 对照实验、受控工具调用、权限与隐私测试、CI 和作品集报告。不训练基础模型，不使用真实客户数据，也不以框架数量衡量项目质量。

## 协作规则

- 导师先提供完整但小步的示例，逐行解释语法、数据变化、设计理由和局限；每次只引入当前需要的知识。
- 学习者先阅读/预测，再在关键处按“文件 → 修改位置 → 修改内容 → 命令 → 预期结果 → 验证”实操；不布置未讲解的大块空白实现。
- 验收看能否解释、预测、做小改动和定位失败，不以默写代码为标准；区分导师提供的代码与学习者完成的改动。
- 调试时提供运行命令、完整错误栈、Python 版本、预期/实际结果；删除密钥和个人信息。
- 每阶段记录实验条件、失败案例、指标和反思；没有实测就不写“显著提升”。
- 仅使用虚构、公开可授权或已获准的资料。模型密钥只从环境读取，不进入 Git 或聊天。
- 后续新增框架前检查官方文档和兼容版本，锁定依赖；旧教程中的 API 不是默认实现标准。
